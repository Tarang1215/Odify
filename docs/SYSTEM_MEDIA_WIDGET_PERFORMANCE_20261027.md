# 2026-10-27: 프레임 드랍 / One UI 9 곡 정보 / 홈 위젯

어제 [인계 문서](HANDOFF_20261026_COMPANY_TO_HOME.md) 이후 집에서 추가 작업 없이 같은 브랜치에서 재개했다. 작업 대상은 `native-android/`이며, 기존 Flutter 작업 폴더는 건드리지 않았다. 폰은 Galaxy S25 Ultra, Android 17(API 37), One UI 9(90000). 시작 설치 버전은 preview12.53(65)이었다.

## 프레임과 실제 원인

먼저 고정 서명 CI의 .54를 설치하고 실제 라이브러리/일시정지 전용 harness로 측정했다. 실제 음악 재생, 준비, 오디오 디코딩은 하지 않았다. 오늘 아티스트 순서가 달라져 측정 대상은 `ODIFY_BENCHMARK_ARTIST=아이유`로 지정했다. 도구는 이제 대상 이름을 환경 변수로 바꿀 수 있고 실패 당시 UI XML/오류 로그도 저장한다.

### 오늘 .54 기준 측정

| 동작 | p95 ms | 최대 프레임 ms | 100ms 초과 |
| --- | ---: | ---: | ---: |
| Home 상하 반전 | 30 | 40.6 | 0 |
| 아티스트 가로 이동 | 11 | 17.2 | 0 |
| 아티스트 곡 목록 상하 반전 | 14 | 19.4 | 0 |
| Explore↔Home | 18 | 36.5 | 0 |
| 국가 페이지 본문 좌우 | 14 | 28.0 | 0 |

첫 Home 반전 측정은 최대 17.6ms/p95 19ms였지만 다음 회차는 40.6ms/p95 30ms여서 첫 결과만으로 완전히 해결됐다고 판단하지 않았다. 어제 .53의 Home 이동 최대 188.9ms보다 오늘 긴 정지는 줄었지만, OS/라이브러리/캐시 상태도 달라 엄밀한 동일 조건 A/B는 아니다. .54는 화면을 유지하고 렌더 레이어로 움직여 재진입 시 전체 구성을 새로 만들지 않는다.

잔여 Home 반전의 메서드 샘플링에서 경계 변형을 위한 CPU signed-distance 계산과 Android `Path.op` 연산이 보였다(3.14초 메인 샘플 중 nOp exclusive 약 50ms). 미니플레이어의 liquid neck 테두리에 Compose BorderModifier가 매번 경로 차집합을 만드는 대신, 이미 같은 외곽선으로 잘리는 렌더 레이어 안에서 stroke를 직접 그리도록 했다. 안쪽에 보이는 두께/색상은 유지한다. 정적인 내비게이션 테두리는 기존 경로 유지. 이 추가 변경은 .56이다.

**추가 디자인 제약:** 사용자는 성능 개선 때문에 예쁜 유리 효과가 약해지는 것을 원하지 않는다. 향후에도 굴절/가장자리 반사/탁함/합쳐지는 움직임을 보존하면서 공유 계산·재사용·메인 스레드 작업 제거를 우선한다. 이번 stroke 변경은 블러/굴절 강도를 낮추지 않는다. 이전 .53의 블러 배경 1/2 해상도 처리는 미세 질감에 영향을 줄 수 있는 별도 변경이며, 전경 글자/아이콘은 원래 해상도를 유지한다. 새 화면 캡처에서 가장자리와 반투명 재질을 확인했지만 과거 UI와 픽셀 단위로 같다고 주장하지 않는다. [Apple GlassEffectContainer](https://developer.apple.com/documentation/swiftui/glasseffectcontainer)도 여러 효과를 함께 렌더링해 성능과 morph를 개선한다고 명시한다. 칩 성능 부족으로 단정하거나 효과를 단순한 차콜 판으로 대체하지 말 것.

## One UI 상태바/Now bar 정보

삼성 전용 비공개 상태바 API나 임의의 지속 알림으로 우회하지 않는다. Android 공식 MediaSession/MediaStyle 설명 경로를 개선한다.

- YouTube 세션이 활성화되거나 PLAYING/BUFFERING으로 보이기 **전에 완성된 메타데이터를 먼저 게시**한다. 이전에는 활성/재생 상태부터 알리고 나중에 제목을 붙였다.
- 공식 TITLE/ARTIST와 함께 DISPLAY_TITLE / DISPLAY_SUBTITLE / DISPLAY_DESCRIPTION 및 표지 비트맵을 채운다. Media3 곡 항목에도 displayTitle/subtitle을 명시한다.
- 로컬 음악 오디오 속성, 세션을 열 Activity, TRANSPORT 알림 분류, 제목 ticker를 명시한다. 제목/아티스트가 빈 문자열이면 전송 영상 정보로 대체한다.
- 재생 길이만 갱신될 때 이미 받은 커버를 비우고 다시 디코딩하지 않는다. 파일 경로가 실제로 바뀔 때만 비동기 재로딩하며, 늦은 옛 커버가 새 곡에 덮어쓰지 않게 한다.
- 현재 공식 곡 표시 정책 및 커버/라이브의 YouTube 썸네일 예외는 유지한다.

이 수정은 시스템에 보내는 정보 누락/순서에 대한 것이다. 회사에서는 실제 PLAYING 상태를 만들지 않으므로 **실제 음악 재생 중 삼성 상태바 제목 표시까지 검증했다고 주장하지 않는다**. 시스템이 순간적으로 무엇을 노출할지는 One UI도 결정한다. 증상이 남으면 재생 중 현재 세션/알림을 곡별로 비교하되 실제 재생 검사는 사용자 허용 환경에서 한다.

참고: [Android 시스템 미디어 컨트롤](https://developer.android.com/media/implement/surfaces/mobile), [Samsung Now bar](https://www.samsung.com/us/support/answer/ANS10004605/).

## Odify 홈 위젯

표준 RemoteViews 위젯을 추가했다. 기본 4×2, 가로/세로 크기 조절 가능. 반투명 그라데이션, 얇은 테두리와 원형 버튼으로 앱의 재질을 이어가며, 공식 앨범 표지/제목/아티스트와 이전·재생/일시정지·다음을 보여 준다. Launcher 바탕을 앱의 실시간 AGSL처럼 굴절시키는 구현은 아니다.

- 추가: 휴대폰 **홈 화면 빈 곳 길게 누르기 → 위젯 → Odify**. 사용자 홈에 자동 배치하지 않는다.
- 네이티브 Drive/Local과 YouTube 서비스의 실제 이벤트에서 같은 표시 상태를 발행한다. 재생 위치 tick은 위젯을 재렌더링하거나 저장하지 않는다. 표지 디코딩은 백그라운드/최대192px로 제한한다.
- 앱의 재생 서비스가 살아 있을 때 버튼은 그 엔진으로 직접 명령을 전달한다. 다른 엔진의 오래된 버튼이나 다음 곡 없는 큐는 거른다.
- 프로세스/세션이 끝났으면 최근 곡 정보는 남기되 재생 중으로 표시하지 않는다. 버튼은 앱 열기로 연결되어 사용자가 곡을 골라 재개한다. 빈 서비스를 멋대로 켜거나 실제로 복원하지 않은 큐를 재생 중처럼 표시하지 않는다.
- Binder 갱신이 완료될 때까지 receiver의 비동기 처리를 유지하며, 추가 주기적 폴링/알람/워크는 만들지 않는다.
- 회사 UI 검사에 provider 등록, 실제 RemoteViews 적용/렌더링, 공식 메타데이터 표시 및 가짜 조작 전달/세션 종료 후 거절을 포함했다. 실제 소리를 내는 명령은 호출하지 않는다.

## 아티스트 목록의 중복 곡(.58)

사용자 추가 요청으로 같은 아티스트 창 안의 표시 중복을 정리했다. 이전 '내 음악' 구역은 파일 ID만 달라져도 MP3/M4A/Drive/YouTube 복사본을 따로 세고 있었다. 표시 목록과 그 목록에서 만드는 재생 큐는 같은 제목의 대표 음원을 하나 선택한다(실제 파일 재생 가능 항목, 로컬 항목, 표지 순 우선). 원본 저장소/파일/기존 플레이리스트는 삭제하거나 재작성하지 않는다.

온라인 목록은 같은 곡의 앨범·싱글·리마스터와 Official Audio/MV/Lyrics 같은 업로드 배지를 정규화한다. 알려진 아티스트 접두어, 대소문자, 전각 문자, 악센트와 구두점 차이를 처리한다. 로컬에 이미 표시한 곡은 아래 '더 많은 곡'에 반복하지 않는다. 제목 일부가 비슷하다는 이유로 합치지 않고, 라이브/커버/리믹스/악기 연주/언어 버전 표기는 남긴다. 검증되지 않은 동일 제목의 라이브 업로드는 영상 ID를 유지해 다른 공연을 실수로 합치지 않는다.

정규식은 공유 인스턴스이며 카탈로그 해석은 IO에서, 화면의 필터 결과는 remember로 유지한다. 스크롤/패널 확장 프레임마다 전체 컬렉션을 다시 대조하지 않는다. `OdifyArtistTracksTest`에 4개 JVM 검사를 추가했고, 실제 아티스트 화면 검사에도 로컬 중복·온라인 중복·이미 보유한 곡의 업로드 변형을 넣어 '내 음악 1곡 / 더 많은 곡 60'이 유지되는지 확인하도록 했다.

## 검증 기록

- .56까지 로컬 JVM 51개 + 앱/AndroidTest 컴파일 통과. .58은 중복 곡 검사 4개를 포함해 JVM 55개 통과.
- .54 UI 검사에서 2개 실패: 비클릭 페이지를 접근성 ACTION_CLICK으로 누르는 잘못된 테스트와 국가 이동 뒤 Android 17의 오래된 접근성 노드 캐시. 첫 검사는 실제 터치 주입으로, 두 번째는 공개 API `UiAutomation.clearCache()`(API34+)로 최신 트리를 읽도록 고쳤다. 화면 캡처에는 일본 페이지가 정상 표시되었다. 손가락을 누른 중간 실제 PagerState 검사는 이미 통과했다.
- .56 고정 서명 CI 성공 후 폰에 업데이트했고, 회사 안전 UI 검사 **11개 전부 통과**. provider 등록 및 실제 RemoteViews 렌더링/제어 연결 검사도 포함한다.
- .56 추가 최적화 측정: Home 반전 p95 **30→17ms**, 최대 **40.6→20.0ms**, jank **7.65→0.27%**(.54와 오늘 같은 기기/아티스트/절차). 나머지 최대치는 아티스트 가로 16.6ms, 목록 반전 48.3ms, Home 이동 41.1ms, 국가 이동 29.9ms. 전 동작 100ms 초과 0회. 목록 반전의 한 프레임은 전 회차보다 길어 전체 구간이 모두 개선됐다고 주장하지 않는다.
- 메타데이터 전용 카탈로그 검사 1개 통과(캐시 포함). 실제 PLAYING/오디오 재생은 미실시.
- .58 [고정 서명 CI 40437879093](https://github.com/Tarang1215/Odify/actions/runs/40437879093) 성공. 정확한 커밋/ZIP SHA256/앱 및 테스트 인증서 확인 후 `install -r`로 폰에 **preview12.58 / 70** 업데이트 완료.
- .58 실기기 회사 UI 검사 **11/11 통과**, 카탈로그 **1/1 통과**. 아티스트의 로컬 중복 파일과 온라인 업로드 변형을 넣고도 '내 음악 1곡 / 더 많은 곡 60'을 유지했다. 확대 패널에서 빠른 스크롤 방향 반전, hidden 페이지 터치/접근성, 손을 누른 동안 국가 PagerState, 위젯 등록/실제 RemoteViews 렌더링도 통과했다.
- .58 최종 반복 측정: Home 반전 p95 **23ms** / 최대 **33.9ms**, Home 이동 p95 **15ms** / 최대 **34.6ms**, 아티스트 가로 최대 **17.8ms**, 목록 반전 최대 **17.5ms**, 국가 이동 최대 **24.1ms**. 모든 측정 구간에서 100ms 초과 **0회**. .56의 17ms보다 Home p95가 높게 나왔으므로 일정 120fps나 프레임 드랍 완전 제거를 주장하지 않는다. [회차별 요약 JSON](performance-20261027/)을 함께 저장했다.
- 최종 화면 켜짐 임시 설정은 원래 **0**으로 복원하고 재조회했다. 미디어 볼륨 **0** 확인. 오늘 .56 시점부터 최종 .58까지 플레이리스트 JSON은 동일하다(4개/140개 곡 참조). 어제 135개 기준과는 2026 재생목록에 5개 추가된 차이가 있으나 기존 항목 제거/테스트 fixture 유입은 없다. 오늘 작업 시작 직전 전체 JSON을 별도 캡처하지 않았으므로 어제부터 변화 시점을 단정하지 않는다. 테스트는 분리된 저장소를 사용하며 원래 라이브러리를 되돌리거나 정리하지 않았다.

서명/패키지/사용자 데이터 보호 규칙은 어제 인계 문서와 같다. 현재 source version .58(70), 앱 코드 커밋 `b7c0ec6e30824e87f41a31a61ff9c64eefd40c23`. PR #21은 아직 draft다. .57에서 첫 foreground 알림도 Chromium 생성 전에 실제 곡으로 초기화하고, 빈 서비스 재개 요청을 종료하도록 보완했다. 위젯의 최소 크기에서도 내용이 잘리지 않게 안쪽 여백을 줄였다.
