## 사용자 의도: 유지할 디자인과 동작

- 핵심은 부드럽고 연결되는 움직임. 갑자기 화면/패널이 교체되거나 차콜 덩어리가 나타나는 느낌을 피한다. 기존 적당히 탁한 liquid glass 가독성을 유지한다.
- 플레이어 아래 양쪽은 50dp 원형 아이콘, 가운데는 같은 높이 알약. 가운데 첫 페이지는 `Drive` / `YouTube` / `Local`, 옆으로 스와이프하면 다음 곡 제목만. 앨범 사진/부가 설명/페이지 점은 넣지 않는다.
- 가사 있으면 바로 가사, 없으면 추가/수정 메뉴. 상단 ⋮ 메뉴는 누른 위치 근처 위쪽에서 열기.
- 플레이리스트 화면은 전체 화면, 이름과 커버 수정 가능. 대기열 순서는 실제 다음 재생 순서와 일치하고 드래그 중 깜빡이지 않아야 한다.
- Home: 아티스트 → Made for you(하위 믹스들) → mood별 발견. 아티스트/무드에는 저장소 밖의 새 곡도 제공한다.
- 정식 음원은 공식 제목/아티스트/앨범 표지, 색상도 그 표지 기준. **커버/라이브 영상은 유튜브 썸네일 사용**. 명시적으로 음원만 교체했을 때는 원래 곡 메타데이터 유지.

## 어디까지 구현/확인했나

### 이전 단계(.52까지)

플레이리스트 전체 화면/이름/개인 커버 변경, 플레이어 아이콘과 출처↔다음 제목 캡슐, 가사 진입, 상단 메뉴, 패널 핸들 확장/축소, 큐 항목별 안정 키/순서 처리, Home 재배치와 온라인 아티스트/무드 발견을 구현했다. RESCENE의 로컬 곡 외 카탈로그와 아티스트 사진을 확인했다.

YouTube 전송 정보와 공식 음원 표시 정보를 분리했다. 예: ROSÉ의 Messy는 공식 제목/ROSÉ/F1 앨범 표지를 표시하며 플레이어 색과 알림도 같은 표시 정보를 사용한다. 커버/라이브 영상은 예외 정책을 적용한다. 알림 MediaSession의 메타데이터 갱신, 제어 전달, 일시정지 알림 해제와 종료 처리 및 혼합 큐 이력을 수정했다. 회사에서는 가짜 일시정지 상태/콜백만 검증했고 실제 소리를 재생하지 않았다.

### .53: 실제 멈춤 원인 제거와 메뉴/제스처 수정

- 기기 샘플링으로 아티스트 사진 로딩 직전 **메인 스레드에서 전체 곡 비교 + Regex 매번 컴파일**이 실행됨을 확인했다. 약 2.8초 추적 중 ICU regex compile 단독 시간이 2106ms였다. 정규식 재사용 + 백그라운드 아티스트별 제목 인덱스 + 이미 만든 차트 인덱스 재사용으로 변경했다.
- Explore 국가 전환을 실제 `HorizontalPager`로 교체했다. 손을 떼고 전환하던 방식 대신 손가락에 맞춰 페이지가 움직인다. 장르 가로 목록은 별도 스크롤이다.
- BIG Naughty 사진은 실제 존재한다. Apple 아티스트 페이지의 `/FeaturesNNN/` 사진 경로도 허용하도록 수정했다. 앨범 `/MusicNNN/` 이미지와 신뢰하지 않는 호스트는 계속 거른다. 라이브 메타데이터 검사에서 사진을 확인했다.
- 플레이리스트 상단 ⋮와 관리 메뉴를 누른 컨트롤 근처의 공통 상단 메뉴로 변경했다.
- 확장 패널 배경은 창 좌표 기준으로 샘플링하는 `OdifySnapshotLens.kt`를 추가했다. 패널 크기가 변할 때 초기 작은 배경을 무작정 늘리는 경로를 대체했다. 플레이리스트 배경은 캐시된 블러, 미니플레이어/내비게이션 배경 필터는 절반 해상도 사용. 전경 텍스트는 원래 해상도를 유지한다.
- Material3 1.3.1의 별도 시트 드래그가 리스트 역방향 제스처를 가져가는 것을 막는 nested-scroll 경계를 적용했다. 확장 핸들은 유지한다.

### .54: 구현/컴파일 완료, 폰 검증 남음

- `OdifyPageLayer.kt`: Home/Explore 구성을 탭 사이에 유지하고 210ms 렌더 레이어 이동/투명도로 전환한다. 숨긴 화면은 배치하지 않고 접근성 대상에서 제외한다. 활성 페이지는 나가는 화면으로 터치가 통과하지 않게 한다. 기타 화면은 전환 종료 후 제거한다.
- Home의 유한한 7개 섹션을 세로 스크롤 Column으로 유지해 방향을 바꿀 때 아티스트 구성이 계속 사라졌다 생기지 않도록 했다. 내부 가로 목록은 lazy 상태 유지.
- 아티스트 인덱스 준비를 기다려 초기 사진마다 중복 전체 검색을 시작하지 않도록 했다. 공유 차트/필터 결과도 재사용한다.
- 페이지 유지/숨김/터치 차단 회귀검사 추가. 국가 드래그 검사는 오래된 접근성 bounds 대신 실제 `PagerState`를 손을 누른 중간에 확인하도록 수정했다.
- **로컬 JVM 51개 검사 + 앱/AndroidTest Kotlin 컴파일 통과. CI APK/테스트 APK 생성 성공. 실기기 설치와 검사/성능 재측정은 아직 안 함.**

   git switch --track origin/codex/company-debug-20261026
   # 이미 로컬 브랜치가 있으면 해당 브랜치로 switch 후, 상태 확인하고 pull --ff-only

2. USB 디버깅 승인 후 설치 버전/설정부터 읽는다. 회사 임시 화면 켜짐 설정 원래 값은 `0`. 복원 명령을 보냈으나 종료 시 USB가 끊겨 최종 확인 못 했다. 필요하면 `adb shell settings put global stay_on_while_plugged_in 0`. 회사 미디어 볼륨은 0으로 유지했다. 라이브러리는 마지막 기준 4개 플레이리스트/135개 곡 참조였으며, 종료 후 최종 비교는 못 했다. 폰 데이터 삭제 금지.

3. 위 성공한 CI에서 `Odify-Native-Stable-Preview-debug`와 `Odify-V12-AndroidTest`를 받는다(보관 14일). 실행 커밋이 **a9f8607...**인지 확인한다. APK 패키지/버전/인증서 확인 후 `adb install -r`로 각각 업데이트한다. **앱 삭제/데이터 초기화/새 키 생성/서명 우회/앱 ID 변경 금지.** 로컬 빌드 키가 다르면 CI APK를 사용한다. 만료됐으면 같은 브랜치 워크플로를 다시 실행한다.

## 성능 측정 재현 자료

`tools/company-debug/`에 이번 제스처 측정 스크립트를 옮겼다. README의 환경/화면 크기 제한을 먼저 읽는다. Android 쪽 `OdifyCompanyScrollHarness`는 추적되어 있어 집에도 전달된다. 일시정지 표시만 주입하고 실제 플레이어 서비스가 없음을 검사하며, 종료 시 원래 이력을 복원한다.

원본 전체 trace/APK/개인 라이브러리 덤프는 회사 PC의 ignored `.tools`/`.local`에만 남고 GitHub에는 올리지 않았다. 위 익명 성능 요약과 재현 스크립트는 GitHub에 보존했다. 회사의 절대 경로나 이전 채팅 없이 이 문서/PR/추적된 소스로 이어갈 수 있다.
