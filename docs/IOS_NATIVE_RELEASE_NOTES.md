Odify iPad / iPhone 1.1.0 (15), iOS/iPadOS 26 이상, LiveContainer용 미리보기입니다.

빌드 15: 현재 Android APK의 음악 앱 경험을 iOS 이식 기준으로 삼습니다.
기존 앨범 표지·재생바·버튼·Liquid Glass 화면을 유지하고, YouTube는
앱 내부 WKWebView / IFrame 재생 엔진으로 전환했습니다. iOS의 기본
YouTube 재생은 직접 오디오 주소를 추출하지 않습니다. 알려진 영상 ID는
바로 재생하고, 카탈로그 곡은 공개 검색 결과에서 아티스트·제목이 맞는
영상을 연결합니다. 검색에 사용자 확인이 필요하거나 영상이 제한되면
오류를 표시합니다. 자동 재생 허용이나 서비스 접근을 보장하지 않습니다.
음악 화면의 재생·일시정지·탐색·대기열 재정렬과 Web/Local/Drive 전환을
같은 제어 계층에 연결했습니다. 곡 전환에는 같은 웹 플레이어를 재사용합니다.
화면 꺼짐·장시간 재생·시스템 조작의 Android 동등성은 실제 iPad에서
검증해야 합니다. 사설 API, 페이지 가시성 위조나 무음 유지음은 사용하지 않습니다.
아래 빌드 14까지의 직접 오디오 수신 설명은 이전 실험 경로에 해당합니다.

빌드 14: YouTube 음원 구간 요청이 401/403/429로 거절되면 해당 소스의 추가
요청을 멈추고, 현재 곡은 로딩 상태에서 즉시 벗어나 오류를 표시합니다.
다음 곡 준비가 거절되면 다른 곡들을 연속 조회하지 않습니다. 사용자가 직접
선택하는 ‘YouTube에서 열기’를 추가했습니다. 이는 외부 앱·브라우저로 여는
기능이며 Odify 내부 대기열을 제어하지 않습니다. 서버의 접근 거절을 해제하거나
앱 내부 YouTube 재생을 보장하는 수정은 아닙니다.
홈 공개 차트 JSON은 이미지·HTML 검색과 분리된 연결 풀과 앱 식별 헤더를
사용합니다. 실제 iPad에서의 시간 초과 해결 여부는 별도 확인이 필요합니다.

빌드 13: 홈 추천 조회가 실패해도 앱 전체 오류 팝업을 띄우지 않습니다.
저장된 추천과 보관함을 먼저 표시하고, 홈 안에서 다시 불러올 수 있습니다.
추천은 기기에 저장해 다음 실행 때 바로 표시합니다. 음악 정보·YouTube 검색
요청의 대기 시간을 제한하고 연결 실패 안내에 서비스와 오류 코드를 표시합니다.
홈 추천 실패와 실제 오디오 수신 실패는 기기 내 진단에서도 구분합니다.
아래 오디오 수신·다음 곡 선행 준비 개선도 모두 포함합니다.

빌드 12: YouTube 오디오 수신을 바이트 단위 처리에서 크기가 제한된 데이터
묶음 처리로 변경했습니다. 겹치는 구간 요청을 합치고 최대 약 1MB의 메모리
버퍼를 유지하며, 곡을 해제하면 지웁니다. 일시적인 네트워크 오류는 같은
주소에서 한 번만 재시도합니다. 명시적인 접근 거절은 재시도하지 않습니다.
다음 곡은 시작 부분과 재생 정보 구간을 먼저 준비한 뒤 시스템 대기열에
넣습니다. 실제 수신 오류도 개인 정보 없이 기기 내 진단에 남깁니다.
반복 재생에서도 준비된 실제 플레이어 항목이 바뀌면 이후 곡을 보충합니다.
실제 iPad/LiveContainer의 시간 초과 해결 여부, 버퍼링 감소 및 장시간 화면
꺼짐 동작은 별도 기기 검증이 필요합니다.

빌드 11: 전체 플레이어의 큰 기본 슬라이더 손잡이를 없애고, Apple Music에서
영감을 받은 얇고 단정한 재생바로 변경했습니다. 평소 4pt, 터치 중에는 8pt로
부드럽게 반응하며 실제 터치 영역은 44pt를 유지합니다. 드래그 중 시간을 미리
표시하고 손을 놓았을 때 한 번 이동합니다. 곡 변경 시 이전 드래그 상태를
초기화하며 VoiceOver의 5초 단위 조절과 동작 줄이기 설정을 지원합니다.
이전 취소 오류·중복 준비 요청 수정도 포함합니다.

빌드 10: 선택한 곡의 첫 삽입 알림에서 다음 곡 준비를 중복으로 취소·재시작하던
경로를 제거했습니다. 자동으로 다음 곡으로 넘어갈 때에는 이후 곡을 계속 보충합니다.
기기 내 진단에는 실제 재생 시작과 대기열 전환 단계도 개인 정보 없이 남깁니다.
네트워크별 버퍼링과 장시간 화면 꺼짐 동작은 실제 기기에서 별도 확인이 필요합니다.

빌드 9: 곡 변경·추천 목록 갱신·대기열 편집으로 취소된 다음 곡 준비 요청을
재생 실패로 표시하거나 해당 곡을 대기열에서 제외하던 문제를 수정합니다.
오래된 요청의 늦은 오류는 새 대기열에 영향을 주지 않습니다. 실제 다음 곡
준비 실패는 출처와 오류 코드만 기기 내 진단에 남깁니다.

이번 수정: 원격 음원을 사전 검사만으로 거절하던 흐름 제거, 실제 플레이어 오류 안내·재시도,
YouTube 요청과 음원 재생의 User-Agent 일치, 주소 만료 전 갱신,

아티스트 공유용 배너를 실제 고해상도 정사각형 사진으로 변경했습니다.

- iPad 너비에 맞는 탐색 사이드바, 음악 목록, 현재 곡·대기열 패널

- 플레이리스트 이름·커버 편집, 가사 편집, 국가별 인기곡·아티스트 곡 탐색

아래 IPA를 iPad의 Safari에서 다운로드한 뒤 파일 앱에 저장하고,
LiveContainer → ＋ → 파일에서 IPA 선택으로 추가해 주세요.
이미 LiveContainer가 SideStore로 설치되어 있다면 이 IPA를 다시 SideStore에
직접 설치할 필요는 없습니다.

이 릴리스는 기기용 Release 컴파일, 자동 검사 및 시뮬레이터 검증을 통과한 뒤
게시됩니다. 실제 iPad/LiveContainer의 Google 로그인, 백그라운드 장시간 재생,
기기별 프레임 속도 검증까지 완료됐다는 의미는 아닙니다.
Google Cloud OAuth 테스트 사용자로 등록된 계정이 필요하며 테스트 모드에서는
권한이 7일 뒤 만료돼 재로그인이 필요할 수 있습니다.

LiveContainer 게스트의 독립적인 WidgetKit 위젯 등록과 기존 Android 보관함·
플레이리스트 자동 이전은 포함하지 않습니다. 설치 시 기존 앱 데이터를 보존해 주세요.
YouTube 연결은 서비스 변경·지역·네트워크 환경에 따라 실패할 수 있습니다.

Google OAuth 클라이언트 ID는 공개 앱 식별자입니다. 사용자 비밀번호,
인증 토큰, 개인 서명 인증서나 사용자 Drive 파일은 이 릴리스에 포함하지 않습니다.


재생 전용 오디오 설정 오류(-50)를 수정했습니다.
재생 전용 모드에 잘못 지정했던 AirPlay 옵션을 제거하고, 호환되는 재생·백그라운드
오디오 설정을 사용합니다. Unknown error 대신 소스와 실제 오류 코드를 표시합니다.
Drive는 Android와 같은 Odify 음악 폴더들을 위치와 관계없이 찾아 하위 곡을
보관함에 연결합니다. 일반 Drive·공유받은 항목 탐색도 계속 사용할 수 있습니다.
실제 기기의 수정 후 재생 성공·장시간 화면 꺼짐 동작은 아직 별도 확인이 필요합니다.


빌드 8: YouTube는 실제 음원 구간 수신을 먼저 확인하고, 같은 익명 HTTP 설정으로
플레이어의 구간 요청을 처리합니다. 401/403/429는 다른 서버·클라이언트로 우회하지
않고 명시적인 오류로 중단합니다. Drive는 폴더 이름과 위치에 관계없이 audio MIME
파일을 조회하는 전체 음악 탭과, 알려진 폴더가 비었을 때의 음악 조회를 추가합니다.
Drive API 연결 계정도 앱 안에서 대조합니다. 계정 주소는 진단 로그에 남기지 않습니다.
기기 내 재생 진단은 단계·음원 출처·오류 코드만 최대 80개 보관하며, 앱 정보에서
사용자가 직접 내보낼 수 있습니다. 실제 기기 동작은 별도 확인이 필요합니다.
