# Android UI first pass — 2026-10-26

Version: `1.0.0-preview12.38` (50), based on `4b389e7`.

- Home: separate the artist portraits and mix cards with 30dp of breathing room.
- Player: compact, bottom-anchored liquid-glass action sheets; separate labelled lyrics and queue controls. Empty lyrics lead to adding lyrics rather than an inert button.
- Queue: pin the current track, track duplicate entries by identity, follow the drag continuously, animate neighbouring rows and scroll near the edges. Commit once on release. Native playback and the YouTube service both resolve the latest entry identities; manual order disables shuffle.
- Explore: keep the country selector stationary and animate independent chart pages with a directional slide/fade. Background refresh no longer inserts a large progress row into the list.
- Audio replacement: retain the original library ID, album art, title, artist and lyrics. Carry the selected video ID separately through both playback engines and notification metadata.
- Library: open playlists above the tab screen, with a large central cover, playlist metadata and a full track list. Hide the tab bar while retaining the live mini-player. Collection cards, empty states and management sheets use consistent spacing and typography.

Reference: the user's supplied full-screen playlist image, Apple Music's Playing Next interaction, and Spotify's mobile playlist/queue controls. This is an Odify layout using its existing backdrop/refraction renderer.

## Validation

Run local compilation and JVM regressions:

    . .\.local\company-debug\env.ps1
    odify-gradle :app:compileDebugKotlin :app:testDebugUnitTest :app:compileDebugAndroidTestKotlin

The dedicated device class `com.odify.nativeapp.OdifyCompanyUiTest` is office-safe: it never calls `play()` or `prepare()`. It tests actual Media3 order while idle, uses UI callbacks that count (and reject) playback, checks a real drag, and captures player/menu/queue/playlist/Explore screenshots. Do not run the other playback instrumentation suites during the office session.

New installed APKs must come from the existing fixed-signature GitHub workflow. Do not replace the signing certificate or uninstall/clear the user's app.

Audible playback and actual next-track execution are intentionally deferred to a session where the user permits sound testing.
