## 현재 설치와 검증 범위

폰에 설치된 버전은 **preview12.58(70)**이다. 이후 **preview12.60(72)**에 4×1 위젯과 재생 유지/자동 다음 곡 수정을 준비했다. 사용자가 점심 동안 USB를 분리하므로 .60 설치와 실기기 검증은 재연결 후 진행한다. .59/.60의 새 기능을 폰에서 검증 완료했다고 보고하지 않는다.

기존 프레임 측정, 아티스트 중복 정리, .58의 55개 단위 검사/11개 안전 UI 검사/1개 카탈로그 검사 결과는 [앞 문서](SYSTEM_MEDIA_WIDGET_PERFORMANCE_20261027.md)를 참고한다. 라이브러리 비교 기준은 오늘 마지막 확인한 **플레이리스트 4개 / 곡 참조 140개**다. 이전 날짜의 135개로 되돌리지 않는다.

## 준비한 변경

- 기존 4×2와 별도로 **Odify 미니플레이어 4×1** 제공. 좁은 폭에서는 이전 곡 버튼을 숨겨 제목과 조작 영역을 확보하며, 확장하면 큰 레이아웃으로 전환한다.
- 앨범 색을 흐리게 반영한 반투명 재질, 반사광과 테두리를 캐시해서 위젯에도 유리 느낌을 넣었다. 표준 Android 홈 위젯이므로 배경화면을 실시간 굴절시키는 재질은 아니다. 앱 내부의 기존 유리 효과는 이 변경으로 줄이지 않았다.
- 네이티브 시스템 재생 세션에 앱으로 돌아오는 동작을 연결했다. 정식 제목/아티스트/표지는 이전 .58의 세션 변경을 유지한다.
- YouTube의 버퍼링/초기 연결 중에도 재생 서비스와 필요한 wake lock을 유지한다. 일시정지/오류 시 해제한다.
- WebView 렌더러 종료와 45초 이상 무진행 상태에 제한된 재연결을 추가했다. 같은 곡과 위치를 복구하되 최근 10분에 2회까지이며, 사용자 일시정지를 우선한다.
- 재생 위치와 대기열을 비공개 체크포인트로 저장한다. Android가 서비스를 다시 시작할 때 최근 활성 재생을 복구하며, 일시정지/정지 후 오래된 비동기 저장이 자동 재생을 되살리지 못하게 막는다. 사용자의 강제 종료/재부팅까지 자동 재시작한다는 뜻은 아니다.
- 한 곡만 골랐거나 대기열이 끝나면 접근 가능한 기존 컬렉션에서 관련 곡을 최대 6개 준비한다. 이미 지정한 다음 곡 순서와 반복 재생을 우선하며, 기록/중복 녹음을 제외한다. 현재 구현은 인터넷 전체에서 새 곡을 찾는 라디오가 아니므로 후보가 없으면 멈춘다. 끊김 없는 gapless 재생을 보장하지 않는다.
- 늦게 도착한 YouTube 재생/정지 이벤트가 사용자의 마지막 명령을 덮지 못하도록 제어했다. 다음 곡 연결 중 새 일시정지가 오면 그 연결이 뒤늦게 재생을 시작하지 않도록 확인한다.

## 종료 현상과 삼성 상태바에서 확인한 사실

사용자가 음량 0 재생 검사를 허용한 뒤 .58로 실제 네이티브 재생을 확인했다. 시스템 세션과 빠른 설정의 미디어 카드에는 곡 정보와 표지가 정상 표시됐지만, 시간 옆 Ongoing Chip은 표시되지 않았다.

QuickStar의 `quickstar_indicator_hide_ongoing_chip` 원래 값은 **1**이었다. 표시 설정을 일시적으로 확인했지만 칩 표시 성공은 확인하지 못해 원래 값 1로 복구했다. 상태바 문제를 해결 완료로 보고하지 않는다. QuickStar의 내보낸 메인 화면에서 ‘아이콘 표시 → Ongoing Chip’의 현재 스위치를 다시 확인해야 한다. 내보내지 않은 내부 화면 직접 실행은 금지되며, 다른 앱이 앞에 있으면 해당 앱 화면을 읽거나 조작하지 않는다.

자정 이후 앱의 종료 기록에는 WebView 렌더러와 앱의 메모리 부족 종료, 백그라운드 종료가 있었다. 이번 복구 작업의 근거이지만 사용자가 경험한 모든 중단이 같은 이유였다고 단정할 수 없다. 짧은 검사만으로 장시간 종료가 해결됐다고 결론 내리지 않는다.

## 점심 전 종료 상태

Odify만 정지했고, 화면 유지 설정은 원래 값 **0**, 음악 음량은 **0**이다. QuickStar 숨김 값도 원래 **1**로 확인했다. 폰 재연결을 알리기 전에는 기기 검사를 시도하지 않는다.

## 재연결 후 순서

1. 고정 서명 CI의 최신 소스 커밋과 APK 버전/체크섬/인증서를 확인한다. 기존 앱과 테스트 앱에 `install -r`만 사용한다. 앱 삭제, 데이터 초기화, 다른 서명 키 생성은 금지한다.
2. 안전 검사 `OdifyCompanyUiTest` **13개**와 카탈로그 검사를 실행한다. 위젯 360×64, 276×51 이미지와 체크포인트 검사가 포함된다.
3. 별도 **OdifyMutedPlaybackTest 2개**는 실제 재생 검사다. 실행 전과 중간에 음량 0을 확인한다. YouTube 실제 재생, 위젯 일시정지/재개/이전/다음, 시스템 메타데이터, 한 곡 종료 후 자동 연결, 백그라운드 렌더러 복구를 검증한다. 모든 instrumentation 클래스를 한꺼번에 실행하지 않는다.
4. QuickStar Ongoing Chip 설정과 실제 네이티브/YouTube 재생에서 시간 옆 제목 표시를 다시 확인한다. 위젯을 삼성 런처에 놓고 4×1 실제 배치도 확인한다.
5. instrumentation 없이 백그라운드 관찰 도구로 재생을 관찰한다. 필요하면 명시적 옵션으로 Odify의 백그라운드 YouTube 프로세스만 종료해 복구를 검증한다. 개인정보가 포함될 수 있는 화면/로그는 비공개 로컬 폴더에만 둔다.
6. 검사가 끝나면 Odify 재생만 멈추고 화면 유지 설정을 복구한다. 라이브러리 참조를 4개/140개 기준과 비교한다.

## 폰 없이 가능한 검사

`odify-gradle :app:testDebugUnitTest :app:compileDebugAndroidTestKotlin`으로 단위 검사 **60개**와 실기기 검사 소스 컴파일을 확인했다. Gradle이 내보낸 실제 YouTube 페이지 스크립트를 `node --test tools/company-debug/youtube-command-state.test.mjs`로 실행한 **7개** 검사도 통과했다. 이 검사는 가짜 YouTube 객체를 사용하며 네트워크/음악을 실행하지 않는다. 실기기 검사 통과와 구분한다.

`monitor-muted-playback.py --self-test`는 세션 파서만 확인한다. 실제 백그라운드 관찰은 아직 실행하지 않았다.
