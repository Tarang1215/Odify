# 2026-10-27 추가 품질 점검

사용자의 전체 보강 요청에 따라 기존 디자인을 유지하면서 재생·복원·대기열의 연결을 점검했다. 기준 설치는 preview12.64(76), 준비 버전은 **preview12.65(77)**다. 기존 기록은 [위젯/연속 재생 인계](COMPACT_WIDGET_CONTINUITY_20261027.md)에 남아 있다.

## 발견한 문제와 수정

- 일시정지한 YouTube에서 다음/이전 곡으로 넘어갈 때, 특히 Native/Drive와 출처를 바꾸면 새 엔진이 무조건 재생됐다. 두 방향 모두 기존 재생 의도를 전달해 **일시정지는 유지**하고, 실제 재생 중 다음 곡은 계속 재생한다.
- 다운로드가 끝난 곡의 메타데이터 갱신이 현재 YouTube presentation을 로컬 파일 presentation으로 덮을 수 있었다. 제목·아티스트·커버는 갱신하되 선택한 스트림은 유지한다. 이전 곡 기록과 음원 출처 표시도 이 정보를 따른다.
- 혼합 대기열에는 YouTube를 실제 음원 주소처럼 넣지 않는다. Native가 미리 준비할 수 있는 유효한 무음 marker를 사용하고, 왕복 변환 후에도 YouTube 구분을 유지한다. 사용자 음악 파일이나 저장 플레이리스트를 변경하지 않는다.
- 마지막 Native 곡이 끝난 뒤 위젯 재생 버튼에는 앱 내부와 같은 되감기 처리가 없었다. 하나의 제어 함수를 공유해 끝난 곡은 처음부터 재생하고, 버퍼링 중 버튼은 추가 재생 요청 대신 일시정지한다.
- 앱 종료 후 YouTube 체크포인트가 있어도 화면에는 곡/대기열이 없어 이어듣기 어려웠다. 최근 위젯 출처/곡과 일치하는 기록을 읽어 **일시정지 상태로 표시**한다. 앱을 여는 것만으로 재생하지 않으며, 사용자가 재생을 눌러야 서비스를 시작하고 저장 위치에서 재개한다. Native/Drive가 더 최근이면 오래된 YouTube 기록을 복원하지 않는다. Native 대기열의 프로세스 간 복원까지 구현한 것은 아니다.
- 일시정지 위치를 비활성 체크포인트로 저장하고, 명시적 정지/Native 전환은 오래된 기록과 쓰기 토큰을 지운다. 복구 로딩 화면과 새 체크포인트도 원래 위치를 유지한다.
- 같은 영상의 연속 재로드는 영상 ID만으로 이전 문서의 응답을 구분할 수 없었다. 재생 문서마다 버전을 넣어 이전 응답이 새 상태를 덮지 못하게 했다. 종료 중인 서비스도 다른 대기열 항목의 상태를 지우지 않는다.
- 자동 다음 곡 준비가 실패하면 버퍼링에 계속 머무르지 않고 정지/안내 상태로 돌아오며, 다시 시도할 수 있게 했다.
- YouTube 위치가 갱신될 때 대기열 ID/키 목록 전체를 반복 생성하던 부분을 실제 대기열 변경 때만 계산한다. 유리 재질·굴절·화면 해상도를 낮추는 변경은 없다. 새로운 실측 FPS 수치로 표현하지 않는다.

## 검증 현황

로컬 JVM **65개**, 생성된 실제 플레이어 스크립트를 실행하는 JS **9개**, AndroidTest 컴파일을 확인했다. 고정 서명 CI와 기기 설치는 이 문서 작성 시 준비 중이다. 실기기 통과 전 완료로 보고하지 않는다.

실기기 안전 검사는 UI 15개 + 카탈로그 1개, 총 **16개**다. 실제 무음 재생 검사는 별도 `OdifyMutedPlaybackTest` **4개**이며, YouTube 위젯의 재생/정지 및 일시정지 상태의 곡 변경, 끝난 Native 파일 재시작, Native↔YouTube 일시정지 유지, 렌더러 복구와 단일 곡 종료 후 자연스러운 다음 곡 연결을 확인한다. Native 테스트용 WAV는 앱 캐시에 만든 1초 무음 파일이며 종료 시 지운다. MediaStore나 사용자 라이브러리에 등록하지 않는다.

앱 프로세스 종료 후의 화면 복원과 명시적 재개는 실제 음량 0 상태에서 별도로 확인한다. Android가 강제 종료한 프로세스를 자동으로 다시 시작한다고 보장하지 않는다. 이전 .62의 전체 프로세스 종료 관찰은 90초 내 자동 재시작 실패였고, 새 기능은 사용자가 앱을 다시 열어 이어듣는 경로를 보강한 것이다.

휴대폰 검사는 음악 음량 0을 유지한다. 종료 시 재생을 멈추고 화면 유지 설정을 원래 0으로 복구한다. 플레이리스트 기준은 4개/140개 참조다. 앱 ID와 영구 서명 인증서는 변경하지 않는다.
