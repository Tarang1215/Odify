# 2026-10-27 추가 품질 점검

사용자의 전체 보강 요청에 따라 기존 디자인을 유지하면서 재생·복원·대기열의 연결을 점검했다. 기준 설치는 preview12.64(76), 최종 설치 버전은 **preview12.68(80)**다. 기존 기록은 [위젯/연속 재생 인계](COMPACT_WIDGET_CONTINUITY_20261027.md)에 남아 있다.

## 발견한 문제와 수정

- .66 실기기 검사에서 Native 끝난 곡 재시작, 실제 위젯 제어, 일시정지 혼합 대기열은 통과했으나 직후 ForegroundServiceDidNotStartInTimeException으로 프로세스가 종료됐다. 기존 YouTube 서비스가 일시정지/Native 전환으로 foreground에서 내려간 상태에서 새 startForegroundService 요청을 받으면 onCreate가 다시 호출되지 않는데, 승격이 onCreate에만 있었다. 모든 onStartCommand 진입에서도 실제 곡 정보로 즉시 승격해 Android의 기한을 충족한다. 같은 4개 실제 재생 검사로 다시 확인한다.

- 실제 아티스트 메뉴를 열면 밝은 시스템 테마를 따르는 Material 3 1.3.1 창에서 상태바 시계/아이콘이 검게 바뀌어 어두운 배경에 묻혔다. 앱의 어두운 유리 메뉴/대화상자 창에는 밝은 시스템 아이콘을 명시한다. 기기의 테마는 바꾸지 않는다. 원인 확인: [사용 중인 Material 3 소스](https://dl.google.com/dl/android/maven2/androidx/compose/material3/material3-android/1.3.1/material3-android-1.3.1-sources.jar)의 ModalBottomSheet.android.kt는 기기의 isSystemInDarkTheme로 초기 상태를 정한다.

- 실제 보관함에서 플레이리스트를 열자 활성 탭의 양수 z-index 때문에 상세 화면보다 보관함 목록이 앞에 그려지는 문제를 재현했다. 상세 화면에 더 높은 순서와 전체 터치 영역을 지정하고, 상세 화면이 열려 있거나 닫히는 동안 뒤쪽 탭의 접근성 및 가로 탭 전환을 차단한다. 준비된 보관함 구성/스크롤은 유지한다.

- 일시정지한 YouTube에서 다음/이전 곡으로 넘어갈 때, 특히 Native/Drive와 출처를 바꾸면 새 엔진이 무조건 재생됐다. 두 방향 모두 기존 재생 의도를 전달해 **일시정지는 유지**하고, 실제 재생 중 다음 곡은 계속 재생한다.
- 다운로드가 끝난 곡의 메타데이터 갱신이 현재 YouTube presentation을 로컬 파일 presentation으로 덮을 수 있었다. 제목·아티스트·커버는 갱신하되 선택한 스트림은 유지한다. 이전 곡 기록과 음원 출처 표시도 이 정보를 따른다.
- 혼합 대기열에는 YouTube를 실제 음원 주소처럼 넣지 않는다. Native가 미리 준비할 수 있는 유효한 무음 marker를 사용하고, 왕복 변환 후에도 YouTube 구분을 유지한다. 사용자 음악 파일이나 저장 플레이리스트를 변경하지 않는다.
- 마지막 Native 곡이 끝난 뒤 위젯 재생 버튼에는 앱 내부와 같은 되감기 처리가 없었다. 하나의 제어 함수를 공유해 끝난 곡은 처음부터 재생하고, 버퍼링 중 버튼은 추가 재생 요청 대신 일시정지한다.
- 앱 종료 후 YouTube 체크포인트가 있어도 화면에는 곡/대기열이 없어 이어듣기 어려웠다. 최근 위젯 출처/곡과 일치하는 기록을 읽어 **일시정지 상태로 표시**한다. 앱을 여는 것만으로 재생하지 않으며, 사용자가 재생을 눌러야 서비스를 시작하고 저장 위치에서 재개한다. Native/Drive가 더 최근이면 오래된 YouTube 기록을 복원하지 않는다. Native 대기열의 프로세스 간 복원까지 구현한 것은 아니다.
- 일시정지 위치를 비활성 체크포인트로 저장하고, 명시적 정지/Native 전환은 오래된 기록과 쓰기 토큰을 지운다. 복구 로딩 화면과 새 체크포인트도 원래 위치를 유지한다.
- 같은 영상의 연속 재로드는 영상 ID만으로 이전 문서의 응답을 구분할 수 없었다. 재생 문서마다 버전을 넣어 이전 응답이 새 상태를 덮지 못하게 했다. 종료 중인 서비스도 다른 대기열 항목의 상태를 지우지 않는다.
- 자동 다음 곡 준비가 실패하면 버퍼링에 계속 머무르지 않고 정지/안내 상태로 돌아오며, 다시 시도할 수 있게 했다.
- YouTube 위치가 갱신될 때 대기열 ID/키 목록 전체를 반복 생성하던 부분을 실제 대기열 변경 때만 계산한다. 유리 재질·굴절·화면 해상도를 낮추는 변경은 없다. 새로운 실측 FPS 수치로 표현하지 않는다.

## 검증 현황

로컬 JVM **65개**, 생성된 실제 플레이어 스크립트를 실행하는 JS **9개**, AndroidTest 컴파일을 통과했다. 최종 소스는 **d15c5924e0bccc6cae6a42f3020a2aaf899f8f90**, [고정 서명 CI 40462128890](https://github.com/Tarang1215/Odify/actions/runs/40462128890)는 성공했다. CI의 두 ZIP SHA256과 앱/테스트 APK의 기존 영구 인증서를 확인한 뒤 Galaxy S25 Ultra에 업데이트 설치했다. 앱 ID와 사용자 데이터는 유지했다.

최종 .68 실기기 안전 검사는 UI 16개 + 카탈로그 1개, 총 **17개 통과(34.048초)**다. 실제 무음 재생 검사 `OdifyMutedPlaybackTest` **4개도 모두 통과(24.395초)**했다. 실제 런처 위젯의 재생/정지·다음·이전 및 일시정지 상태 곡 변경, 끝난 Native 파일 재시작, Native↔YouTube 일시정지 유지, 렌더러 복구와 단일 곡 종료 후 자연스러운 다음 곡 연결을 포함한다. .66에서 실패했던 동일 검사 순서가 .68에서는 완료됐다. Native 테스트용 WAV는 앱 캐시에 만든 1초 무음 파일이며 종료 시 지운다. MediaStore나 사용자 라이브러리에 등록하지 않는다.

최종 .68에서 `toxic till the end / ROSÉ`를 37.033초에 일시정지한 뒤, 백그라운드의 Odify PID/명령줄을 확인해 해당 프로세스만 종료했다. 앱을 다시 열자 제목과 대기열이 복원되고 재생 세션은 시작되지 않았다. 전체 플레이어에서 재생을 누르자 실제 세션이 41.897초까지 진행했으며, 다시 일시정지한 저장 위치는 43.898초였다. 다음 곡 20개도 유지됐다. .66의 Messy 81초 복원도 선행 확인했다. 이 검사는 사용자 재진입 복원 검증이며, Android가 강제 종료한 프로세스를 자동으로 다시 시작한다고 보장하지 않는다. 이전 .62의 전체 프로세스 종료 관찰은 90초 내 자동 재시작 실패였다.

수정된 플레이리스트 상세의 전체 화면 표시와 배경 목록 접근성 차단, 아티스트 유리 메뉴에서 밝은 상태바 시계/아이콘 유지도 실제 화면으로 확인했다. One UI 빠른 설정의 현재 곡은 정식 `Messy / ROSÉ / F1 The Album` 메타데이터와 앨범 커버로 표시됐다. 앱 메뉴는 밝은 기기 테마에서도 어두운 재질을 유지한다.
